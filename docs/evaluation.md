# Оценка качества

## Что проверяем

Релиз должен пройти четыре независимых уровня.

### 1. Сохранность

- числа, даты, имена, ссылки и цитаты не изменены без разрешения;
- отрицания, условия и степень уверенности сохранены;
- новые выгоды, гарантии и причинность не появились из воздуха;
- обращение к читателю не сменилось случайно.

### 2. Русская речь

- границы предложений сохраняют связи;
- управление и сочетаемость естественны;
- короткие фразы выполняют функцию, а не изображают темп;
- жанровая формальность не считается ошибкой сама по себе.

### 3. Автор и задача

- сильные слова и позиция автора защищены;
- хук соответствует телу и доказательствам;
- CTA существует в брифе;
- текст не превращен в универсальный каркас.

### 4. Техническая чистота

- нет запрещенных кодовых точек, стрелок и служебных следов;
- skill folder переносим и не содержит локальных путей;
- CLI сохраняет JSON-схему и коды завершения;
- два release-архива из одного commit совпадают по SHA256.

## Минимальная пара

Каждый новый паттерн требует:

1. Плохого примера.
2. Исправленной версии.
3. Контрпримера, который должен остаться без изменения.
4. Объяснения жанровой границы.
5. Теста, если правило можно формализовать.

## Слепой forward-тест

Агенту дают путь к скиллу и обычную пользовательскую задачу без подсказки ожидаемого ответа. Проверяющий оценивает сохранность, ясность, голос и ложные срабатывания. Тест считается полезным, только если агент не видел заранее диагноз и эталонную правку.

## Сравнение с другими проектами

Сравнивать нужно на одном исходнике, одном брифе и одинаковом формате ответа. Нельзя считать внутренний score одного проекта общей метрикой качества. Для итоговой оценки нужны независимые русскоязычные редакторы и скрытая принадлежность вариантов.
